# Changelog

Notable changes to QuickMart POS, newest first.

## 2026-11-18

### Added
- **Product variants.** A product can have sizes or flavours, each a product of its own with its own SKU, barcode, price and stock. Add them from the product's edit page; the till shows one card per product and a picker for its options, and search or a scan finds a variant directly. API: `parent_id`, `variant_name`, `group_variants`.
- **Refunds through Paystack.** The card or Mobile Money part of a return is sent back automatically through Paystack's refund API once the return is saved. Each refund shows its Paystack status on the sale, with buttons to retry a failed one or check on a pending one, and a signed webhook (`/api/paystack/webhook`) records when Paystack finishes. `PAYSTACK_AUTO_REFUND=false` turns the automatic sending off.
- **Split payments.** A sale can be paid partly by Mobile Money or card (through Paystack, verified for exactly that part) and the rest in cash, with change from the cash part. Receipts list each part, shift totals count each part under its method, and refunds of split sales pay cash back first (recorded in the new `Refund.cash_amount`).
- **SMS receipts (optional).** A **Text** button on receipts sends a short receipt to the customer's phone through Arkesel or Twilio. Local numbers get the store's country code; only that country can be texted unless more are allowed, and each receipt can be texted at most 3 times. API: `POST /api/sales/:id/sms-receipt`.
- **Promotions.** Managers create automatic percentage discounts for one product, a category, or the whole store, optionally scheduled with start and end times (new **Promos** page). At checkout each line gets the biggest promotion that applies; the till shows it on product cards and cart lines and prices the cart exactly as the server does, and receipts name it. Cashier discounts still apply on top. API: `/api/promotions`.
- **Purchase orders.** Managers order stock from a supplier (new **Orders** page), with suggested quantities for its low-stock products, then receive deliveries in full or in parts. Receiving adds stock with a restock log and can update the product's cost price. Orders can be cancelled; suppliers with orders can't be deleted. API: `/api/purchase-orders`.
- **Sentry error reporting (optional).** Set `SENTRY_DSN` and/or `VITE_SENTRY_DSN` to report unexpected server errors and browser crashes, tagged with the request ID and the user's role. Tokens, cookies, request bodies, query strings and database error details are stripped, and the browser SDK is only downloaded when a DSN is set.
- **Emailed receipts.** An *Email* button on every receipt sends it to the customer's email on file or an address typed at the till, as HTML with a plain-text version. It uses any SMTP provider configured with `SMTP_*` and `MAIL_FROM`; without them the button explains that email isn't set up. API: `POST /api/sales/:id/email-receipt`.
- **Monitoring.** Every request gets an `X-Request-Id` that appears in its log lines and in unexpected-error messages ("ref 3f2a9c1e"). Request logs now include response times. `GET /api/health/ready` checks the database, and Docker Compose starts the web app only once the API is ready.
- **End-to-end tests.** Playwright drives a real browser against the real API and a production build: sign-in and role access, a keyboard checkout from barcode scan to receipt, and a partial return with its refund slip. They run in CI against a freshly seeded database.
- **Loyalty points redemption.** Cashiers can spend a customer's points as money off at the till ("Use Points", with a Max button). An admin sets what a point is worth under Settings → Customer & Loyalty (0 turns it off; the seed uses GH₵ 0.10). Points come off after the cart discount and before tax, are deducted in the sale's transaction so two tills can't spend the same points, and appear as their own line on receipts. Returns give the points back in proportion to the goods returned. API: `redeem_points` on `POST /api/sales`.
- **Refund slips.** Each return in a sale's refund history has a *Print slip* button that prints an 80mm slip with the items returned, the amount, the reason, who processed it, and a signature line.
- **Installable app (PWA).** A web app manifest, icons and a service worker let QuickMart be installed on tablets and desktops. Its screens load without a connection (API calls are never cached), and a banner warns staff when they're offline.
- **Cash drawer shifts.** Open a shift with a counted float and close it by counting the drawer; the expected cash (float + cash sales − cash refunds) and the over/short difference are recorded. Sales and refunds are linked to the open shift. Managers and admins review every shift on the new **Shifts** page and can close shifts left open. An admin setting, *Require an Open Shift to Sell*, blocks charging until a shift is open (on by default in the seed data). API: `/api/shifts`.
- **Partial returns.** `POST /api/sales/:id/refund` takes optional `items` (sale line, quantity, restock) and a `reason`. Each unit is refunded at its share of what the customer paid; the last return refunds exactly what is left. Damaged goods can be refunded without restocking. Sales show `PARTIALLY_REFUNDED`, a refund history, and running `refunded_amount` / `refunded_quantity` totals. Reports, the dashboard and customer spending subtract returns. Loyalty points are reduced in proportion.
- **Docker.** `docker compose up --build` runs PostgreSQL, the API and the web app (nginx) together. See *Or run everything with Docker* in the README.
- **CI.** GitHub Actions lints, tests and builds the server and client on every push and pull request.
- `COOKIE_SECURE=false` allows refresh cookies over plain HTTP on a private network (e.g. shop tablets reaching a Docker install).

### Fixed
- body-parser updated to 1.20.9 for a denial-of-service advisory.
- Transaction numbers now follow the highest number issued that day, so removing one of today's sales can't cause a duplicate ID.
- Card and mobile money: the POS rechecks prices, stock and tax before charging, and retries a failed sale with the same Paystack reference instead of charging the customer again. Cash sales no longer store a payment reference, and non-cash sales record the verified total as the amount paid.
- Tax and totals round half-pesewa amounts up. The profit report counts the cost of fully discounted items. Reports given only an end date default to the 30 days before it.
- Logged-out and rotated refresh tokens are stored in the database, so they stay revoked after a restart.
- CSV exports escape quotes and neutralise spreadsheet formulas.
- Malformed input (repeated query parameters, non-text fields, oversized bodies) gets 4xx responses instead of 500s.
- Several lists ignore stale responses when filters change quickly; the POS shortcuts ignore open dialogs; Enter confirms card and mobile money payments; item discounts appear on receipts; missing status colours were added.
